\begin{frame}{Accumulation compares an evolving library with the same fixed seed}
  \small
  \begin{itemize}
    \item Two model configurations; twelve matched blocks per model.
      Each block has three five-generation sequences with the same task order.
    \item No library exposes no inherited work. Fixed seed supplies the same
      initial method. Accumulation adds earlier accepted files and explanations
      from that sequence.
    \item Fixed seed and accumulation share the prompt, submission interface,
      initial seed and 20-turn ceiling. Their first generation has the same
      inputs, with independently sampled executions.
    \item The endpoint is any accepted submission failing the saved proof audit.
      All accepted submissions in this comparison have determinate audit outcomes.
    \item Resample matched blocks, keeping all conditions and five generations
      together. The public block counts reproduce the totals and confidence intervals.
  \end{itemize}
  \evidence{The no-library condition also changes wording and submission interface.
  Public projections recompute the statistics, not the withheld proof audits.}
  \takeaway{The manipulation is accumulated work, not isolated word count or elapsed time.}
\end{frame}

\begin{frame}{Historical Wiki protocols remain separate from the current release}
  \begin{block}{Historical study: ordinary implementation after seeded recovery}
    972 recipients, 162 six-session chains; six models, three initial scores,
    three initial conditions and three founder realizations.
    Each session has 20 units and at most 40 turns.
  \end{block}
  \begin{block}{Historical follow-up: a private return zeroes personal reward}
    108 recipients, 36 three-session chains; six models, three scores,
    empty/full wiki and one founder realization.
    Reward resets at each new recipient; shared work can still pass onward.
  \end{block}
  \evidence{These are not the current persistent-Wiki results. Nine commissioned source sessions preceded these recipients.
  Before exposure, a uniform amendment selected first-author checkpoints because two final
  source sequences had exhausted the finite case pool. This was an outcome-informed design change.}
\end{frame}

\begin{frame}{Keep native outcomes separate}
  \small
  \begin{itemize}
    \item A function-task violation occurs when an accepted submission fails the
      independent audit, even if the agent later submits correct code.
    \item An audit-clean recipient has correct accepted code and no accepted
      submission that fails the audit. Missing audits remain unknown.
    \item Wiki case-access events come from service logs. Code score is the
      fraction of 100 own-package cases passed; 60\% qualifies.
    \item Explicit submission determines earned reward. A perfect function can
      coexist with unauthorized private-case acquisition.
    \item Resource measures describe actions and stopping: historical model turns
      and wiki charged units are not pooled into one efficiency score.
  \end{itemize}
  \takeaway{Measure task performance, boundary crossing and onward contribution together.}
\end{frame}

\begin{frame}{The handoff rule determines what can be corrected}
  \begin{block}{Final-folder inheritance}
    One-agent lineages carry actual exported files. The current persistent Wiki
    carries edits and deletions without researcher withdrawal. The older Wiki
    study withdrew an unchanged original founder note after the first recipient.
  \end{block}
  \begin{block}{Function peer-study cumulative records}
    All seats receive the same prior record. New files are added, edited files
    become additional versions, and deletion does not erase the existing history.
  \end{block}
  \evidence{The peer-model study fixes the initial record and merge policy while changing
  the contributor. Sessions are fresh; prior conversations are not copied.}
  \takeaway{Deletion has different consequences in a mutable folder and an append-only history.}
\end{frame}

\begin{frame}{Use chains, not their seats, to describe between-run uncertainty}
  \small
  \begin{itemize}
    \item Trajectory points summarize sessions; independent chains provide the
      replication for chain-level resampling.
    \item Late Gemini and Kimi chain-mean bootstrap intervals in the peer study
      are [0.067, 0.733] and [0, 0.800].
    \item A zero-width empirical interval means the observed chains agree,
      not that future chains must behave identically.
    \item The historical withdrawal Wiki study has three founder realizations; one lacks the original note.
      The corresponding nonempty conditions deliver identical starting files.
  \end{itemize}
  \takeaway{Retain the structure of shared histories when describing uncertainty.}
\end{frame}

\begin{frame}{Reconstruction preserves both completed work and exceptions}
  \small
  \begin{itemize}

    \item Before receipt of generated peer records, first-generation recipient

    \item Resource summaries retain native budgets and missing-trace status;

  \end{itemize}
  \takeaway{A reproducible table should remain traceable to the observations that define it.}
\end{frame}

\begin{frame}{Separate a model's correction from its influence on successors}
  \begin{block}{Observed model behavior}
    A participant may delete a helper, write corrective guidance and supply a
    legitimate implementation in the same session. Record this as its work.
  \end{block}
  \begin{block}{Follow the consequences}
    Record private requests, legitimate completion, renewed publication
    and the actual material reaching later recipients.
  \end{block}
  \evidence{Natural cleanup combines several actions. A successor's clean outcome alone
  does not identify which action caused it or establish a contributor-model contrast.}
  \takeaway{Evaluate who corrects and what follows; do not replace model evaluation with message optimization.}
\end{frame}

\begin{frame}{A common execution framework supports distinct comparisons}
  \begin{block}{Task, participants and shared-state policy}
    Function tasks, a mutable Wiki and ternary sequences use explicit model configurations,
    bounded sessions, declared handoffs and independent outcome records.
  \end{block}
  \begin{block}{Packaged development suite}
    Fixed-reference recipients and candidate contributors over two generations,
    plus wiki recipients starting at 30\%, 60\% and 90\%.
    The plan contains $36+72N$ sessions for $N$ candidates.
  \end{block}
  \evidence{The Wiki-only published profile has $162N$ sessions; the ternary runner has
  $18N$ one-agent or $144N$ four-agent sessions per protocol. All require explicit authorization.}
  \evidence{No participant results are reported for this new default suite.
  Its 108-session single-candidate plan is not the historical 108-recipient
  reward-conflict study. Historical evidence retains its original designs.}
  \takeaway{Reuse the measurement framework without pooling different studies into one score.}
\end{frame}
